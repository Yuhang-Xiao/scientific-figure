# Editability Boundaries

Use this reference to decide what should be rebuilt as editable geometry and what should remain an image asset.

## Default Boundary

Make these elements editable:

- Text, panel labels, section headings, legends, citations, captions-in-figure.
- Boxes, lanes, panels, brackets, dividers, callout frames.
- Arrows, connectors, route lines, axes, tick labels, scale bars, data charts, tables.
- Simple geometric symbols that are already clean and deterministic.

Keep these as transparent image assets by default:

- Complex scientific mini-illustrations.
- Highly styled model icons or conceptual glyphs generated by Image2.
- Microscopy-like, anatomy-like, molecular, lab-equipment, sample, sensor, or organism illustrations.
- Any visual whose beauty depends on Image2 texture, lighting, shading, or composition.

Transparent asset means a PNG/WebP with an alpha channel. In PowerPoint it can be moved, scaled, rotated, masked, and replaced, but its internal lines and fills are not individually editable.

## Reference-Guided Boundary

Once an Image2 master or source/reference image exists, the editability boundary must follow that visual contract.

- Complex visual content is regenerated as matching transparent assets one semantic item at a time, using the master/source only as a reference for visual role, style, orientation, proportions, and placement.
- Editable framework content stays native: title bars, numbered circles, labels, legends, frames, arrows, route paths, threshold lines, brackets, tables, charts, and conclusion boxes.
- Do not replace a detailed master/source with a cleaner but structurally different native-vector redraw. Beauty does not excuse missing master elements.
- Do not merge independently positioned master/source objects into one broad asset when doing so hides route marks, legends, cloud/rain groups, state tiles, or small icons.
- Do not describe a transparent image or SVG wrapper as internally editable. It is movable/scalable/replaceable only.

## When Full Vector Editability Is Required

Use this decision order:

1. Prefer a user-provided, licensed, official, or domain-standard SVG/vector source.
2. If the icon is simple and flat, try automatic vectorization with Inkscape Trace Bitmap, Potrace, or VTracer.
3. If vectorization changes the visual identity, creates too many nodes, damages edge quality, or diverges from the Image2 master, stop and keep it as a transparent asset.
4. If the user insists on editable paths, create a side-by-side preview: original transparent asset versus vectorized candidate, and ask for approval before using the vectorized version.

## PowerPoint Notes

- SVG files can often be inserted into PowerPoint and converted/ungrouped into editable Office shapes, but results vary by SVG complexity and Office version.
- Complex vectorized artwork may become thousands of shapes and make the PPTX slow or fragile.
- Never simplify the scientific meaning or Image2-approved composition merely to make paths editable.
